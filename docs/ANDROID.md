# CRM для Android — план

Ветка `android`. Здесь ведётся всё, что относится к приложению для телефона;
в `main` попадает только готовое и проверенное.

## Зачем

Сейчас телефон открывает CRM в браузере по адресу офиса. Для этого нужны белый IP,
открытый порт на роутере и установка сертификата на каждый телефон. Приложение
убирает все три условия: оно подключается **по ключу сервера**, как программа на
компьютере (способ 1 в «Удалённом доступе»), и шифрует трафик от телефона до офиса.

## Что получит сотрудник

1. Устанавливает приложение (файл APK по ссылке или QR-коду от владельца).
2. Сканирует QR-код с ключом подключения, вводит PIN ключа.
3. Вводит логин, пароль и код из приложения-аутентификатора.
4. Дальше — значок CRM на экране телефона и вход по отпечатку пальца.

Внутри — та же CRM, что в браузере телефона: «Мои», «Клиенты», «Чаты», «Поиск».

## Как это устроено

Приложение — оболочка Tauri 2 для Android вокруг уже существующего кода:

| Часть | Откуда берётся | Что нужно сделать |
|---|---|---|
| Подключение по ключу, туннель, проверка связи | `crm-connect`, `crm-p2p` (Rust) | собрать под Android, без изменений в логике |
| Экраны «Мои серверы», «Добавить сервер», «Проверить» | `crm-desktop/ui` | вынести в общую папку, адаптировать под узкий экран |
| Сама CRM | веб-интерфейс сервера | ничего: открывается в окне приложения через локальный туннель |
| Одобрение устройств, код из приложения, лимиты | сервер | ничего: телефон — такое же устройство, как ноутбук |

Новый крейт `crates/crm-mobile` (Tauri mobile). `crm-desktop` не трогаем: в нём
управление сервером, служба Windows и трей, которых на телефоне нет.

Чего в приложении **нет**: запуска сервера, работы без связи с сервером,
удалённого рабочего стола.

## Этапы

Каждый этап заканчивается проверяемым результатом. Следующий не начинается,
пока предыдущий не проверен на настоящем телефоне.

### Этап 0. Разведка

Цель — убедиться, что основа вообще работает на Android, до любой работы над экранами.

- Пустое приложение Tauri для Android, в которое собраны `crm-connect` и `crm-p2p`.
- Сборка APK в GitHub Actions (Android SDK и NDK, цели `aarch64`, `armv7`, `x86_64`).
- Жёстко заданный ключ тестового сервера → окно открывает страницу входа CRM.

**Готово, когда:** телефон на мобильном интернете (без Wi-Fi) открывает страницу
входа тестового сервера по ключу, а в «Проверить» видно «напрямую» или «через узел связи».

**Что может не получиться и что тогда:**
- библиотека iroh не собирается или не работает под Android → берём её
  официальную обёртку для Kotlin и пишем тонкий мост;
- окно Android не открывает `http://127.0.0.1` → разрешаем это в настройках
  сети приложения (только для локального адреса);
- мобильный оператор не даёт прямых соединений → связь идёт через узел связи;
  это ожидаемо, измеряем скорость.

### Этап 1. Рабочая версия

- «Мои серверы», добавление сервера: вставить ключ или **сканировать QR-код** камерой.
- «Подключиться», страница «устройство не одобрено», «Проверить» с адресами.
- Постоянный ключ устройства в закрытом хранилище приложения.
- Прикрепление файлов и фото из CRM (выбор файла, камера), скачивание файлов в «Загрузки».
- Кнопка «Назад» телефона, поворот экрана, вырезы и системные панели.
- Переподключение при смене сети (Wi-Fi ↔ мобильный интернет) без повторного входа.

На сервере: в «Сервер» → «Вход с телефона» появляется блок «Приложение для Android»
с QR-кодом ключа подключения.

**Готово, когда:** сотрудник с нуля проходит путь «установил → сканировал →
вошёл → открыл задачу → написал в чат → приложил фото» без подсказок.

### Этап 2. Удобство и защита

- Блокировка приложения отпечатком пальца или PIN-кодом телефона.
- Уведомления о новых сообщениях и сроках, пока приложение открыто или свёрнуто недавно.
- Тёмная тема по настройке телефона, крупный текст по настройке телефона.
- «Поделиться» из других приложений → прикрепить к задаче (если останется время).

**Готово, когда:** потерянный незаблокированный телефон не даёт открыть CRM
без отпечатка, а владелец отзывает устройство в «Устройствах вне офиса».

### Этап 3. Уведомления, когда приложение закрыто

Android останавливает закрытые приложения, поэтому здесь нужен выбор (см. «Решения»):

- **Постоянное соединение** (значок CRM в шторке): работает без сторонних сервисов,
  расходует батарею, на части телефонов система его всё равно останавливает.
- **Служба уведомлений Google (FCM):** надёжно и экономно, но требует сервисов
  Google на телефоне, учётной записи Firebase и отправки с сервера сигнала
  «есть новое» через Google (без текста сообщения).

**Готово, когда:** сообщение в чате задачи приходит уведомлением на телефон
с закрытым приложением в течение минуты.

### Этап 4. Выпуск и обновления

- Ключ подписи приложения (хранится у владельца репозитория, в секретах сборки).
- Раздача APK: сервер CRM сам отдаёт установщик по ссылке и QR-коду.
- Приложение проверяет новую версию на своём сервере и предлагает обновиться.
- По решению — публикация в магазине приложений.

**Готово, когда:** обновление с версии N на N+1 ставится на телефон сотрудника
без потери сервера в списке и без повторного одобрения устройства.

## Проверка качества

- Автотесты Rust (`crm-connect`, `crm-p2p`, сервер) уже покрывают подключение,
  одобрение устройств и лимиты — приложение использует тот же код.
- В сборке: компиляция под Android и запуск приложения на эмуляторе с проверкой,
  что открылась страница входа.
- Вручную перед каждым выпуском: два телефона (новый и старый Android),
  три сети (офисный Wi-Fi, домашний Wi-Fi, мобильный интернет), включение VPN.

## Безопасность

- Трафик зашифрован от телефона до сервера; узел связи его не читает.
- Новый телефон вне офиса ждёт одобрения владельца; подключавшийся в офисе одобряется сам.
- Вход вне офиса — с кодом из приложения-аутентификатора, как на компьютере.
- Ключ устройства и список серверов лежат в закрытой папке приложения;
  на этапе 2 доступ к приложению закрывается отпечатком.
- Потерян телефон → владелец нажимает «Отозвать» в «Устройствах вне офиса»
  и завершает сеанс в «Активных входах».

## Решения, которые нужны от владельца

1. **Как раздавать приложение:** файл APK со своего сервера (быстро, без проверок
   магазина; сотрудник разрешает установку из неизвестных источников) или магазин
   (Google Play, RuStore: привычнее, но нужна учётная запись разработчика и проверка).
2. **Нужны ли уведомления при закрытом приложении** и каким способом (этап 3).
   Без них этапы 0–2 и 4 дают полноценное приложение.
3. **Минимальная версия Android.** Предлагается Android 8 и новее.
4. **Нужен ли iPhone.** Тот же код собирается и под iOS, но нужны компьютер Mac
   для сборки и платная учётная запись разработчика Apple. В этот план не входит.

## Порядок работы в ветке

- Ветка `android` регулярно подтягивает `main`, чтобы не расходиться с сервером.
- Каждый этап — серия небольших коммитов с тестом и описанием «Зачем / Что / Проверка».
- В `main` этап вливается после проверки на телефоне; сборка APK при этом
  становится частью общей сборки рядом с установщиком для Windows.
- Изменения сервера, нужные приложению (QR-код ключа, раздача APK), делаются
  в `main` отдельными коммитами: они полезны и без приложения.

## Известные ограничения

- Через узел связи большие файлы идут медленно; на мобильном интернете это
  будет основной путь.
- Публичный узел связи — сторонний сервис с ограничением скорости. При активной
  работе с телефонов стоит поднять свой.
- Сведения о сборке Tauri и iroh под Android взяты из их документации и на
  наших крейтах ещё не проверены — для этого и нужен этап 0.
